# Raw measurements behind the paper

These are the raw per-trial measurements behind every table and figure of

> **2SDIF: A Serverless Dual Channel Oracle for Data in Transit Integrity in Blockchain Enabled Fog IoT Systems**
> (under review, Journal of Systems Architecture)

Nothing here was edited by hand. The CSV and JSON files were written by the benchmark scripts in this
repository, and `results_values.tex` was generated from them by `scripts/stats.js`.

## Files

| File | Contents |
|---|---|
| `latency_azure.csv` | store path, 50 trials, local chain + Azure witness, 6 Oct 2026 |
| `retrieve_azure.csv` | retrieval with verification |
| `rtt_azure.csv` | HTTPS round trip to the witness |
| `device_cost.csv` | digest and HMAC cost |
| `gas_hardhat.csv` | gas per operation under Osaka |
| `attacks_remote.csv` | T1–T7 against the deployed Azure witness |
| `attacks_hardhat.csv` | T1–T7 in-process |
| `environment.json` | host and tool versions |
| `latency_sepolia.csv` | 20 trials on Sepolia after Glamsterdam, 7 Oct 2026 |
| `sepolia_run.json` | deployment gas, block range, RPC |
| `results_values.tex` | every number in the paper, as LaTeX macros, generated by `scripts/stats.js` |

Times are in milliseconds, except `device_cost.csv` (microseconds per record). The latency files hold one row per
measured trial; the warm-up trials (10 for the Azure run) were discarded by the benchmark and are not in the files.

## How the numbers in the paper were produced

From the repository root (Node.js 20 or later; `stats.js` needs no dependencies):

```bash
node scripts/stats.js --latency paper_results/latency_azure.csv --retrieve paper_results/retrieve_azure.csv --gas paper_results/gas_hardhat.csv --device paper_results/device_cost.csv --attacks paper_results/attacks_remote.csv --rtt paper_results/rtt_azure.csv --sepolia paper_results/latency_sepolia.csv --sepolia-run paper_results/sepolia_run.json --warmup 10 --template paper_results/results_values.tex --out <out>.tex
```

`<out>.tex` then matches `paper_results/results_values.tex` line for line, apart from the two generated header
lines at the top (`%% Generated by scripts/stats.js on <timestamp>` and `%% Not measured in this run ...`), which
carry the time of the run. A `<out>.summary.json` with the full statistics (n, mean, 95% CI, median, p95, min,
max, standard deviation) is written next to it.

`stats.js` reports the mean with a 95% confidence interval (Student's t), the median and the 95th percentile
(linear interpolation). The paper reads the macros from `results_values.tex`, so no number is typed into the text
by hand.

## Setup

- **Fog node:** a Windows 11 laptop (Core i5-8250U, 16 GB), running the local Hardhat chain (Osaka hardfork,
  automine), the gateway and the device simulator on one host.
- **Witness:** Azure Functions Flex Consumption (Node 22) in UAE North, with Table Storage and Key Vault.
- **Sepolia:** via publicnode, one day after its Glamsterdam upgrade.

Exact host and tool versions are in `environment.json`; the Sepolia contract address, block range and RPC client
are in `sepolia_run.json`.

## The Azure resources no longer exist

The Azure resources were deleted after the measurements. The function URL in `environment.json` no longer
resolves. To repeat the cloud runs, deploy your own witness with `scripts/azure.js` (or `run_azure.ps1` on
Windows), as described in the top-level README.
